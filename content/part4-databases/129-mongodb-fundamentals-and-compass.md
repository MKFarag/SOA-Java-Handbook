## Overview
MongoDB is a distributed, document-oriented NoSQL database that stores flexible, schema-free JSON-like BSON documents, queried via the MongoDB Query Language (MQL) and MongoDB Compass GUI.

---

### Relational (RDBMS) vs MongoDB Terminology Mapping

| Relational (RDBMS) Concept | MongoDB Equivalent | Description |
| :--- | :--- | :--- |
| **Database** | Database | Physical container for collections |
| **Table** | Collection | Group of schema-flexible documents |
| **Row (Record)** | Document | BSON formatted JSON object |
| **Column** | Field | Key-value pair within a document |
| **Primary Key (PK)** | `_id` Field | Unique 12-byte `ObjectId` generated by default |
| **JOIN** | Embedded Documents or `$lookup` | Denormalized nesting or aggregation stage |
| **Index** | Index | B-Tree index structure on document fields |

## Setting Up Local MongoDB & MongoDB Compass

### 1. Running MongoDB via Docker
```bash
docker run --name mongodb-dev \
  -p 27017:27017 \
  -d mongo:7.0
```
*(MongoDB listens on default port `27017`.)*

### 2. Visual Management with MongoDB Compass
**MongoDB Compass** is the official visual GUI for exploring, querying, and managing MongoDB databases:
1. Download MongoDB Compass from [mongodb.com/try/download/compass](https://www.mongodb.com/try/download/compass).
2. Launch Compass and connect to the default local URI:
   ```text
   mongodb://localhost:27017
   ```
3. Click **Create Database**:
   - Database Name: `ecommerce`
   - Collection Name: `products`
4. You can visually view documents, run queries in the Filter bar, build aggregation pipelines, and inspect indexes.

## Core Document Structure & BSON Types

A MongoDB document is stored in BSON format, supporting rich types like dates, 64-bit integers, and binary ObjectIds:

```json
{
  "_id": ObjectId("655f1a2b3c4d5e6f7a8b9c0d"),
  "sku": "LAPTOP-PRO-16",
  "name": "Developer Workstation 16",
  "price": 1899.99,
  "stock": 42,
  "inStock": true,
  "tags": ["developer", "hardware", "sale"],
  "specs": {
    "cpu": "12 Cores",
    "ramGb": 32,
    "ssdGb": 1024
  },
  "createdAt": ISODate("2026-11-21T10:00:00Z")
}
```

## Fundamental CRUD Operations Reference

### 1. Create: `insertOne()` & `insertMany()`
```javascript
// Insert a single document:
db.products.insertOne({
  sku: "KEY-01",
  name: "Mechanical Keyboard",
  price: 89.99,
  stock: 25
});

// Insert multiple documents:
db.products.insertMany([
  { sku: "MOU-02", name: "Wireless Mouse", price: 29.50, stock: 100 },
  { sku: "MON-03", name: "4K Monitor", price: 349.00, stock: 12 }
]);
```

---

### 2. Read: `find()` & Query Operators
```javascript
// Find all products in collection:
db.products.find({});

// Filter by exact match:
db.products.find({ name: "Mechanical Keyboard" });

// Numerical range comparison ($gt, $gte, $lt, $lte):
db.products.find({ price: { $gte: 50.00, $lte: 200.00 } });

// In list ($in):
db.products.find({ sku: { $in: ["KEY-01", "MOU-02"] } });

// Querying nested fields (using dot notation):
db.products.find({ "specs.ramGb": 32 });

// Projection (include only name and price, exclude _id):
db.products.find({}, { name: 1, price: 1, _id: 0 });

// Sorting and Paging:
db.products.find({})
  .sort({ price: -1 }) // 1 = Ascending, -1 = Descending
  .skip(10)
  .limit(10);
```

---

### 3. Update: `updateOne()` & `updateMany()`
Always use update operators like **`$set`** or **`$inc`** to modify specific fields without overwriting the entire document:

```javascript
// Set a field value:
db.products.updateOne(
  { sku: "KEY-01" },
  { $set: { price: 79.99, onSale: true } }
);

// Atomically increment a counter (prevents race conditions):
db.products.updateOne(
  { sku: "KEY-01" },
  { $inc: { stock: -1 } } // Decrements stock by 1
);
```

> [!CAUTION] Never Omit Update Operators!
> In older MongoDB APIs, executing `db.products.update({ sku: "KEY-01" }, { price: 79.99 })` would completely **replace the entire document** with just `{ price: 79.99 }`, erasing all other fields! Always use `$set` or use modern `updateOne()`.

---

### 4. Delete: `deleteOne()` & `deleteMany()`
```javascript
// Delete first document matching criteria:
db.products.deleteOne({ sku: "OBSOLETE-99" });

// Delete all matching documents:
db.products.deleteMany({ stock: 0 });
```

## MongoDB Aggregation Pipeline Reference

The **Aggregation Pipeline** is MongoDB's framework for multi-stage analytics, transforming documents sequentially through discrete stages:

```text
Raw Documents ---> [$match Filter] ---> [$group Aggregation] ---> [$sort] ---> Final Output
```

### Realistic Example: Revenue by Category
```javascript
db.orders.aggregate([
  // Stage 1: Filter paid orders only
  { $match: { status: "PAID" } },

  // Stage 2: Group by customerId and calculate total spend & order count
  {
    $group: {
      _id: "$customerId",
      totalSpent: { $sum: "$totalAmount" },
      orderCount: { $sum: 1 }
    }
  },

  // Stage 3: Filter customers who spent at least $100
  { $match: { totalSpent: { $gte: 100.00 } } },

  // Stage 4: Sort by total spend descending
  { $sort: { totalSpent: -1 } }
]);
```

## Pitfalls

- **Unbounded Array Growth (16MB BSON Ceiling):** MongoDB strictly enforces a 16MB maximum document size. Storing unbounded arrays (such as millions of historical audit records inside an `auditLog: []` field) will eventually crash write operations with `Document exceeds maximum allowed BSON size`. Reference historical logs in separate collections.
- **Document Overwrite Hazard:** In raw MongoDB updates, omitting operator flags like `$set` causes the document to be replaced entirely with the passed payload, stripping away all existing fields. Always use `$set` or `$inc` with `updateOne()`.
- **Collection Scans (`COLLSCAN`) on High-Volume Queries:** Querying nested or top-level fields without a supporting compound index forces MongoDB to scan every document in the collection. Always verify query execution paths with `.explain("executionStats")` to ensure `IXSCAN` index usage.

## Practice

### Q: Why does using `$inc: { stock: -1 }` in MongoDB prevent inventory race conditions compared to reading the document, decrementing in Java, and saving with `$set`?
<details data-type="solution">
<summary>Reveal Answer</summary>

> **Answer:** Reading a document, calculating `stock - 1` in Java memory, and saving it via `$set` creates a classic Read-Modify-Write race condition: two concurrent threads may both read `stock = 5` simultaneously and both write `stock = 4`, losing an inventory decrement. In contrast, MongoDB executes `$inc` atomically directly within the WiredTiger storage engine under document-level latching, guaranteeing that all concurrent updates serialize correctly.
</details>
